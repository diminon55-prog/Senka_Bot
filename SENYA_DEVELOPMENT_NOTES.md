# Сеня: заметки по поиску марки по артикулу

## Реализованный сценарий

- Пользователь может отправить артикул командой `/findarticle <артикул>` или обычным текстом, например `COVANI SMS25-BHLM3` либо `SMS25-BHLM3`.
- Прямой ввод артикула распознаётся локально и не отправляется в Gemini.
- Локальный классификатор требует, чтобы модель одновременно содержала буквы и цифры. Строки вроде `HELLO-WORLD` и `123-456` не запускают OCR.
- Поиск выполняется только в текущем PDF конкретного Telegram-чата, а не во всей истории документов.
- Для одной найденной марки бот отправляет размеченный PDF с HTML-карточкой: артикул, лист, порядковый номер на листе, источник и остаток.
- Порядковый номер считается по физической сетке листа слева направо и сверху вниз, начиная с 1. Пропущенный при чтении Data Matrix код не сдвигает номера остальных ячеек.

## Разметка PDF

- Найденная ячейка целиком получает зелёную заливку и зелёную рамку.
- Стандартная прозрачность заливки — `0.28`, поэтому Data Matrix и текст остаются видимыми.
- Разметка создаётся через PyMuPDF поверх исходной страницы.
- Возвращаемое имя файла имеет суффикс `_marked.pdf`.

## Текущий документ и база данных

- В SQLite добавлена таблица `chat_state` с `current_document_id` для каждого `chat_id`.
- Текущий PDF сохраняется после перезапуска процесса.
- Повторная загрузка уже известного PDF снова делает этот документ текущим.
- Поиск по артикулу после перезапуска не откатывается к старому PDF.
- Импорт PDF и поиск по артикулу одного чата сериализованы общим `RLock`.
- Если поиск приходит во время загрузки нового PDF, он ждёт завершения импорта и затем работает с новым текущим документом.
- Разные чаты по-прежнему могут обрабатываться параллельно.

## OCR и индекс артикулов

- Сначала используется текстовый слой PDF.
- Для сканированных страниц применяется системный `tesseract-ocr` с английской моделью.
- OCR выполняется лениво, постранично и останавливается после нахождения нужного количества свободных марок.
- Полностью обработанные страницы сохраняются в `article_index_pages`.
- Страница считается полностью проиндексированной только тогда, когда артикул получен для каждой сохранённой на ней марки.
- Неполный OCR не возвращает ложное сообщение «марка не найдена»: поднимается `ArticleOcrError`, а пользователь получает предложение повторить запрос.
- Непустые частичные результаты OCR накапливаются между попытками. Пустой результат следующей попытки не стирает уже распознанный артикул.
- Одновременный OCR ограничен семафором: в одном экземпляре `MarksInventory` обрабатываются не более двух страниц, включая создание больших растров PyMuPDF.
- Поиск допускает отсутствие слова `COVANI` в результате OCR и умеет находить базовую модель без конечного варианта артикула.

## CSV-текстовый индекс

- Для готового CSV с колонками `Номер`, `Набор`, `Лист`, `Ряд`, `Колонка`, `Название`, `Код` добавлена отдельная таблица `mark_text_index`.
- Исходная таблица `marks` и полный Data Matrix не заменяются: текстовый индекс связан с канонической маркой через `mark_id`.
- Связь строится по физическому адресу `Лист + Ряд + Колонка`; координаты марки в PDF переводятся в сетку 8×8.
- В индексе отдельно сохраняются полное поисковое название и короткий код из CSV. Оба поля доступны обычному `/findmark`.
- Из `Название` дополнительно извлекается артикул, когда он соответствует формату модели. Для запроса `COVANI SMS25-BHLM3-015H` найдено восемь свободных индексных кандидатов.
- `_extract_article` распознаёт кириллические модели и числовые артикулы вида `181-7А` (минимум одна буква и одна цифра, размеры вроде `36-37` игнорируются). Бренд `COVANI` подставляется префиксом, когда встречается в названии.
- Артикулы у уже импортированных марок можно доизвлечь скриптом из `display_name` (обновляются только строки с пустым `article`); 2026-10-31 так доизвлечены 23 артикула в рабочей БД, резервная копия `data/backups/marks-before-article-reextract-20261031T183705Z.db`.
- Запрос `/findmark COVANI ...` локально направляется в поиск по артикулу, поэтому не попадает в старый поиск только по Data Matrix/названию документа.
- Полный индекс из 721 строки отключает резервный OCR. Если индекс неполный, OCR остаётся доступным и недостающие страницы можно распознать повторно.
- Импорт CSV проверяет UTF-8, точный набор столбцов, границы сетки, дубли координат и пустые обязательные поля до записи. Запись параметризована, атомарна и идемпотентна.
- CSV можно отправить боту как документ после PDF; он импортируется до ветки распознавания PDF.

## Надёжность выбора и отправки

- Каждому выбору присваивается уникальный `claim_token`.
- Марки выбираются атомарно в SQLite через `BEGIN IMMEDIATE`.
- После успешной отправки PDF в Telegram выбор подтверждается и токен очищается.
- Если `send_document` завершается исключением, только марки этого токена возвращаются в статус `available`.
- Чужой чат или устаревший токен не может освободить уже подтверждённую марку.
- Незавершённые токены восстанавливаются при следующем запуске однопроцессного бота, чтобы аварийное завершение до отправки не оставляло марку списанной навсегда.

## Основные точки реализации

- `bot.py`
  - распознавание обычного текстового ввода артикула;
  - `tool_find_article`;
  - обязательный текст с порядковым номером;
  - отправка размеченного PDF;
  - подтверждение или освобождение `claim_token`.
- `marks_inventory.py`
  - миграции SQLite;
  - хранение текущего документа;
  - локальный индекс артикулов;
  - OCR и накопление частичных результатов;
  - расчёт `position_on_page`;
  - зелёная разметка PDF;
  - резервирование, подтверждение и восстановление марок;
  - синхронизация импорта и поиска.
- `test_bot_marks.py`, `test_marks_inventory.py`
  - регрессионные тесты прямого ввода, текста ответа, текущего документа, OCR, конкурентной загрузки, разметки и восстановления марок.

## Возврат марок и ревизия

- `unselect_marks(chat_id, query, quantity)` ищет среди марок со статусом `selected` по полному Data Matrix, артикулу, поисковому названию из CSV, короткому коду или названию документа и возвращает найденные марки в `available` с очисткой `selected_at` и `claim_token`.
- При совпадении нескольких марок сначала возвращаются самые недавно выбранные (`ORDER BY selected_at DESC`).
- Выборка атомарна (`BEGIN IMMEDIATE`), поэтому параллельные команды не могут вернуть одну и ту же марку дважды.
- Марки доступных статусов и чужих чатов не затрагиваются.
- `reset_inventory(chat_id)` сбрасывает все выбранные марки чата в `available` без переимпорта PDF.
- `/export` спрашивает формат кнопками: «Excel (точка с запятой)» или «Текст (запятая)» — `export_selected_marks(chat_id, delimiter)` поддерживает оба; по умолчанию «;».
- `/resetmarks` требует подтверждения inline-кнопками («Да, сбросить всё» / «Отмена»), мгновенного сброса больше нет.
- Команды бота: `/unmark [N] <запрос>`, `/export`, `/resetmarks`.

## Голосовой поиск марок

- `handle_voice` скачивает голосовое (OGG/Opus), `transcribe_voice` отправляет аудио напрямую в Gemini (`generate_content` через `call_with_503_retry`) и получает дословную текстовую транскрипцию.
- Дальше текст идёт по той же логике, что и текстовое сообщение: паттерн артикула → локальный `tool_find_article`, иначе локальный `tool_find_marks` по названию, и только если марки не нашлось — обычный диалог с Gemini.
- Текстовый поиск не изменён: голос — отдельный хендлер, регрессион покрыт тестами `test_voice_*`.
- Пустая или неразборчивая речь возвращает просьбу повторить, без вызова диалога.
- В стоимость Gemini голосовая транскрипция входит как обычный запрос и учитывается в `/stats`.

- Поиск по артикулу умеет искать по префиксу (`COVANI DLT-S26-WLM3`), но если под префикс подходят несколько разных артикулов, бот отказывается выбирать и просит уточнить полный артикул — чтобы случайно не списать марку с другим суффиксом.

## Множественный выбор марок

- `find_available_by_article(chat_id, article)` находит все свободные марки по артикулу или названию.
- При нескольких совпадениях бот показывает пронумерованный список с inline-кнопками: по кнопке на марку (`sel:1:<id>`), плюс «📦 Все» (`sel:all:0`) и «❌ Отмена» (`sel:cancel:0`). Текстовый ввод номеров или «все» работает параллельно.
- `claim_specific_marks(chat_id, mark_ids)` выбирает конкретные марки по ID, создаёт размеченный PDF и claim_token.
- Состояние ожидания выбора хранится в `pending_mark_selection`; «отмена» или кнопка «Отмена» сбрасывает его.
- В строках списка дубликатов и блоке «📍 Расположение» указывается документ марки (📄 product_name или имя файла), чтобы было видно, в каком PDF искать лист.

## Документы чата

- `list_documents(chat_id)` — список PDF чата со счётчиками марок и флагом текущего; `set_current_document(chat_id, document_id)` переключает текущий документ без перезагрузки файла.
- `/documents` — HTML-список документов с inline-кнопками переключения (`doc:<id>`); `/usedoc N` — переключение по номеру из списка.
- `/findarticle` работает только по текущему документу; `/findmark` и простой текст ищут по всем документам чата.
- `/findarticle` и `/findmark` без аргумента переводят чат в режим ожидания запроса (`pending_command_input`): бот спрашивает артикул/название, следующее текстовое сообщение уходит в поиск, «отмена» выходит из режима.
- `/unmark` без аргумента спрашивает код/название/артикул; при нескольких выбранных совпадениях показывает список с кнопками возврата (`unm:1:<id>`, `unm:all:0`, `unm:cancel:0`). Текстовый ввод номеров/«все» тоже работает. `unselect_specific_marks(chat_id, mark_ids)` возвращает конкретные марки в `available` атомарно.
- Повторный запрос уже выбранной марки (по артикулу, названию или Data Matrix с фото) отвечает «⚠️ уже выбрана ранее» с документом, листом, №, рядом/колонкой и датой в МСК. Подсказка `/unmark` использует артикул марки, а не полный Data Matrix.
- Локальный поиск по словам из названий (цвет, модель): текст вроде «оранжевый еще есть?» ищется в `mark_text_index` без Gemini; совпадения показываются списком с inline-кнопками «Отметить»/«Все»/«Отмена» через `find_available_by_words`.

## Фото, галереи и сетевые сбои

- Telegram передаёт альбом отдельными сообщениями, поэтому каждое фото обрабатывается независимо и может выполняться параллельно с соседними фотографиями.
- Фото не создаёт новую строку марки. Если локально распознан ровно один Data Matrix, бот ищет уже импортированную из PDF марку и переводит существующую запись `available → selected`; три разных читаемых кода из базы на трёх фото дадут три выбранные записи. Повторный или неизвестный код новую запись не создаёт.
- Если на одном фото распознано несколько Data Matrix, бот ничего не выбирает и просит прислать один код крупным планом.
- До скачивания обычного фото бот показывает Telegram-индикатор `typing`. После локальной проверки Data Matrix, пока работает Gemini, исходное фото получает редактируемый `<blockquote>` с короткой IT-шуткой.
- Используется пул из 12 фраз на чат: порядок перемешивается, повторы исключены до исчерпания пула, доступ защищён `Lock` для параллельных worker-потоков фотоальбома. Готовый ответ Gemini заменяет статусное сообщение, не засоряя чат.
- Из ответа Gemini извлекается только явно подписанный артикул (`артикул`, `article`, `Арт.`, `ART.NO`). Сначала `tool_find_marks` ищет его по готовым индексам во всех документах; OCR текущего документа используется только как резерв. Свободное описание фото без артикула остаётся обычным диалогом и не запускает поиск/списание марки.
- `get_file` + `download_file` повторяются только при временных сетевых ошибках (`timeout`, `connection aborted/reset`, `broken pipe`). Повтор ограничен идемпотентной загрузкой: глобальные повторы Telegram-отправок не включены, чтобы не дублировать сообщения и документы.
- Сбой отправки промежуточного статуса не отменяет распознавание: итог отправляется отдельным plain-text reply. Невалидный Markdown от Gemini сначала повторно отправляется без `parse_mode`.
- Пользователь больше не получает сырой текст исключения. Сетевой сбой показывается понятным сообщением, прочие ошибки — нейтральным ответом; полный traceback записывается только в серверный `logs/senya-*.log`.

## HTML-оформление ответов о марках

- Ответы с разметкой отправляются с `parse_mode="HTML"`: `send_claimed_document` и `reply_text` включают его автоматически, если в тексте есть теги. Telegram поддерживает только `<b>`, `<i>`, `<u>`, `<code>`, `<blockquote>` и т.п. — цветных таблиц в Bot API нет.
- Список дубликатов артикула: жирный номер, название, под ним отступ `└` с курсивом «лист X, №Y».
- Успешный выбор одной марки: жирный заголовок + карточка в `<blockquote>` (артикул в `<code>`, лист, № на листе, источник, остаток).
- `claim_location_details` строит блок «📍 Расположение:» — по строке на марку: `<code>артикул</code> │ название │ <u>л.X №N (р.R, к.C)</u>`.
- Все пользовательские данные (артикулы, названия, имена файлов) экранируются через `html.escape` до вставки в разметку.
- Повторный запрос уже выбранной марки отвечает «⚠️ Марка уже выбрана ранее» с датой и временем выбора: `selected_at` хранится в UTC (SQLite `CURRENT_TIMESTAMP`), а выводится конвертацией в МСК (`format_selected_at_msk`, UTC+3, формат `дд.мм.гггг чч:мм МСК`).
- Локальный классификатор артикула (`PLAIN_ARTICLE_PATTERN`) понимает кириллицу: текстовое сообщение вида `181-7А` идёт сразу в локальный поиск без Gemini. Размеры без букв (`36-37`) по-прежнему не считаются артикулами.

## OCR-индексация названий без CSV (сессия 2026-11-05)

- Для PDF «MARKI_A3_1_soderzhimoe_nomera.pdf» (document_id=2, 244 марки, 4 листа, product_name «Новая партия») названия отсутствовали: текстового слоя нет, CSV-индекс не присылали, поле `marks.article` было заполнено старым OCR только у 108 марок, причём у 6 из них article ошибочно содержал код Data Matrix (вида `01...`).
- Установлен системный пакет `tesseract-ocr-rus`; OCR выполнен моделью `eng+rus` при 300 DPI, режим `--psm 11`, вывод TSV с координатами и уверенностью.
- Для каждой марки собраны OCR-строки, чей центр попадает в ячейку сетки (x0..x1, y0..y1 из `marks`). Шум отфильтрован: коды Data Matrix (паттерн `^01\d{13}`), номер позиции (голое число 1–3 цифры), строки логотипа «Честный знак» (по `честн|знак|3HAK`), строки без букв/цифр, строки с conf < 60 и без кириллицы длиной < 4. Лидирующие/висячие «слабые» токены (без кириллического слова ≥3 букв, латинского слова ≥2 букв или цифры) отрезаны.
- Результат записан в `mark_text_index` (244 строки, INSERT-only, `ON CONFLICT` не понадобился). Позиции (page_number/row_number/column_number) вычислены из `position_on_page` по сетке 8×8, `short_code` — из полного кода марки (символы с 32-го).
- Второй проход исправил OCR-искажения артикула в начале названия (`[7649-12` → `F7649-12`, `ОН-2Н` → `DH-2H`): если normalized display_name не содержал normalized `article`, артикул подставлен в начало (заменой искажённого первого токена или дописыванием). Одновременно 6 dm-подобных «арти́кулов» в `marks` сброшены в пустую строку.
- Третий проход — эстетическая чистка: удалены мусорные токены (одиночные обломки, строчная латиница ≤3 букв, артефакты без цифр). Осмысленные короткие слова (жен/мальч/сер/орт/мод и т.п.) сохранены белым списком. Изменено 95 из 244 названий.

## Ограничения

- Архитектура восстановления незавершённых `claim_token` рассчитана на один запущенный экземпляр бота.
- OCR мелкого текста зависит от качества исходного PDF и может потребовать повторного запроса.
- Поиск нескольких марок работает внутри выбранного текущего PDF; объединение результатов из разных PDF в один ответ не реализовано.
- Интерфейса ручной отмены уже подтверждённого выбора пока нет — вместо него команда `/unmark` ищет марку по запросу и возвращает её в `available`; «отзеленить» уже отправленный PDF нельзя.
- CSV-индекс применяется к текущему PDF чата. При нескольких документах перед импортом нужно сделать нужный PDF текущим повторной загрузкой.
- Поисковое название хранится для всех 721 строк, но структурированный `article` извлекается только из названий, где модель соответствует поддерживаемому шаблону; обычный поиск по полному названию при этом работает для всех строк.
- Фотоальбом не является одной пакетной транзакцией: каждое фото выбирает максимум одну уже существующую марку и отвечает отдельно; общего итогового PDF/отчёта по всему альбому пока нет.
