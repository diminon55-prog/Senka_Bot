# Проект «Сеня»

## Назначение и запуск

- Рабочий каталог: `/root/test_gemini`.
- Это Telegram-бот на Python с Gemini, обработкой PDF и учётом марок «Честного Знака».
- Виртуальное окружение: `/root/test_gemini/gemini_env` (Python 3.14).
- Запуск: `cd /root/test_gemini && ./gemini_env/bin/python bot.py`.
- Polling запускается только через `run_bot()` под `if __name__ == "__main__":`, поэтому `bot.py` можно безопасно импортировать в тестах.
- Не выводить и не копировать в чат содержимое `.env`, Telegram-токен, Gemini API key и полные Data Matrix из реальной базы.

## Основные файлы

- `bot.py` — Telegram-обработчики, Gemini, меню, PDF/A3, интеграция учёта марок.
- `marks_inventory.py` — распознавание Data Matrix через `zxing-cpp`, SQLite-учёт, поиск и зелёная разметка PDF.
- `cz_processor.py` — сборка файлов печати и резки «Честного Знака».
- `settings.py` — загрузка настроек из проектного `.env`.
- `.env.example` — перечень настроек без секретных значений.
- `requirements.txt` — зафиксированные зависимости.
- `test_marks_inventory.py`, `test_bot_marks.py`, `test_bot_retry.py`, `test_config.py` — регрессионные тесты.
- `SENYA_DEVELOPMENT_NOTES.md` — подробное состояние реализации поиска марки по артикулу: архитектура, SQLite/OCR, надёжность, проверки и ограничения. В новой сессии перед продолжением этой функциональности обязательно прочитать файл целиком.

## Возможности бота

- Текстовый диалог и анализ фото, видео и PDF через Gemini.
- `/draw <описание>` — генерация изображения через Imagen.
- `/spusk` — A3-раскладка последнего PDF.
- ZIP/RAR с PDF — сборка печати и резки «Честного Знака».
- `/stats` — число запросов и токенов Gemini.
- `/reset` — сброс только диалогового контекста, без удаления базы марок.
- `/help` или постоянная кнопка `ℹ️ Что умеет Сеня?` — справка по возможностям и командам.
- При запуске регистрируется стандартное меню команд Telegram.

## Учёт марок

- PDF с марками загружается один раз. Новый PDF добавляет новую партию в существующую базу текущего Telegram-чата.
- Подпись `Название: <товар>` назначает название всему загруженному документу. Без подписи название формируется из имени файла.
- `/findmark <полный Data Matrix или название>` выбирает одну свободную марку.
- `/findmark N <название>` выбирает до N свободных марок.
- `/findarticle <артикул>` ищет свободную марку по напечатанному артикулу в текущем документе, выделяет её зелёным и сообщает номер листа и позицию на листе (слева направо, сверху вниз).
- `/findarticle N <артикул>` выбирает несколько свободных марок этого артикула и перечисляет позиции каждой.
- `/findarticle` и `/findmark` без аргумента спрашивают артикул/название следующим сообщением; «отмена» выходит из режима.
- При нескольких совпадениях артикула бот показывает список с inline-кнопками выбора (по кнопке на марку, «Все», «Отмена»); текстовый ввод номеров тоже работает.
- `/documents` показывает загруженные PDF чата со счётчиками марок и кнопками переключения текущего документа; `/usedoc N` — переключение по номеру.
- В ответах о найденных марках указывается документ (📄 название товара или имя файла), лист, № на листе, ряд и колонка.
- `/unmark [N] <код, название или артикул>` возвращает ошибочно выбранные марки в статус `available` (по умолчанию одну, самую недавно выбранную из совпавших).
- `/unmark` без аргумента спрашивает код/название/артикул; при нескольких выбранных совпадениях показывает список с кнопками возврата (по кнопке на марку, «Все», «Отмена»); текстовый ввод номеров тоже работает.
- `/export` спрашивает формат кнопками (Excel «;» или текст «,») и выгружает все выбранные марки чата в CSV (артикул, название, документ, лист, позиция, время выбора, короткий код) для ревизии.
- `/resetmarks` сбрасывает все выбранные марки чата обратно в `available` только после подтверждения inline-кнопкой — для тренировки на живой базе или начала нового учёта без переимпорта PDF.
- `/list` показывает все выбранные марки чата таблицей (артикул, название, лист, позиция).
- `/markstats` показывает всего, выбрано и свободно.
- Выбранная марка получает прозрачную зелёную заливку и рамку в возвращаемом PDF; её статус меняется с `available` на `selected`.
- Фото одного Data Matrix распознаётся локально: бот ищет точный код, выбирает марку, присылает размеченный PDF и уменьшает остаток.
- Голосовое сообщение транскрибируется через Gemini (аудио вход, `transcribe_voice`): артикул уходит в локальный поиск по артикулу, название — в поиск марок, остальное — в обычный диалог. Текстовый поиск при этом не меняется: голос — отдельный хендлер.
- Если на фото распознано несколько Data Matrix, бот ничего не списывает и просит прислать крупно один код.
- Если Data Matrix на фото не распознан, фото обрабатывается обычным мультимодальным сценарием Gemini.
- Полный Data Matrix идентифицирует одну уникальную марку. Режим «все марки того же товара по GTIN» пока не реализован.
- Артикулы извлекаются локально: из текстового слоя PDF, а для сканированных страниц — через системный `tesseract-ocr` на английской модели. Индекс строится постранично до нахождения нужного количества свободных марок; уже обработанные страницы сохраняются, поэтому повторная загрузка не нужна.
- `position_on_page` — физическая позиция марки на конкретном листе, начиная с 1, в порядке слева направо и сверху вниз. Пропущенный при декодировании Data Matrix не сдвигает номера следующих ячеек.

## Хранилище и изоляция

- SQLite: `/root/test_gemini/data/marks.db`.
- Исходные PDF: `/root/test_gemini/data/marks_pdfs/`.
- Данные разделяются по `chat_id`.
- Состояние переживает перезапуск бота; `/reset` его не очищает.
- Один и тот же PDF в одном чате определяется по SHA-256 и повторно не импортируется.
- Защиты от одинакового Data Matrix в двух разных PDF пока нет: уникальность действует только внутри одного документа.
- `.env`, база и PDF должны оставаться с приватными правами (`600` для файлов, `700` для каталогов).

## Настройки

Все runtime-настройки находятся в `.env` и читаются через `settings.py`: модели Gemini/Imagen, лимиты файла и повторов, polling, пути базы/PDF, DPI сканирования, геометрия сетки, прозрачность выделения, максимальное количество марок за запрос, `MARKS_OCR_DPI`, `MARKS_TESSERACT_COMMAND`, `MARKS_OCR_TIMEOUT_SECONDS`, `MARKS_OCR_MAX_PAGES` и `MARKS_OCR_TOTAL_TIMEOUT_SECONDS`. Реальные секреты никогда не добавлять в `.env.example`, исходники, тесты, документацию или git.

Для OCR артикулов нужен системный пакет `tesseract-ocr` версии 5 или новее; это не Python-зависимость и через `pip install -r requirements.txt` не устанавливается.

## Известные ограничения и риски

- Название товара относится ко всему PDF; распознавания разных товарных названий внутри смешанного листа нет.
- OCR мелкого текста не идеален. Поиск допускает ввод артикула без варианта после базовой модели и умеет искать модель, даже если OCR пропустил слово `COVANI`. Интерфейса принудительной переиндексации уже успешно обработанной страницы пока нет.
- Нет allowlist пользователей, rate limit и лимита расходов Gemini/Imagen.
- Отмена ошибочного выбора реализована командой `/unmark`, но она не «отзеленивает» уже отправленный PDF: марка возвращается в статус `available` только в базе.
- Архивы и загруженные PDF частично держатся в RAM; большие распакованные архивы могут исчерпать память.
- `handle_ai_error()` всё ещё может показать пользователю подробный текст исключения; перед публичным доступом ошибки нужно санитизировать.
- Старый Telegram-токен раньше находился в исходнике. Он удалён из кода, но его следует считать скомпрометированным до перевыпуска через BotFather.
